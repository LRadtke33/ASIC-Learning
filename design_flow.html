Lesson 8 / 84 · Part I, Foundations

The Design Flow and Its Files: RTL to GDS

An ASIC is designed as a sequence of steps, each done by a specific tool that reads the previous step’s files and writes new ones. This lesson walks through every step — what happens, which tool does it, and what you check — and names the files in between.

What you will learn

  • Follow a digital design through each step from specification to tapeout: what happens, what goes in and comes out, and which tool does the work.
  • Follow an analog block from schematic to a macro that the digital flow can place.
  • Say what each file describes — netlist, Liberty, LEF, DEF, SDC, SPEF, SPICE, GDS — and what each check before tapeout proves.

1. From behavior to polygons

A digital ASIC is designed as a chain of transformations. Each step reads files, produces files, and either throws away detail the next step does not need or adds detail the previous step did not have.

It starts with RTL (register-transfer level): a description of the circuit as registers and the logic between them, written in a hardware description language such as Verilog and checked by simulation. Synthesis translates the RTL into a gate-level netlist: a list of standard-cell instances and the nets (named connections) between their pins. A standard cell is a small pre-designed, pre-characterized circuit — an inverter, a NAND gate, a flip-flop — with a fixed height so that cells line up in rows. Place and route then turns the netlist into geometry: a floorplan and power grid, cell placement, a clock tree, and wires. Signoff checks the result, and the final layout is written out as GDS for tapeout.

For SKY130 the open-source flow is LibreLane, the successor to OpenLane. It is a conductor, not a single tool: it runs Verilator, Yosys, OpenROAD (which includes the OpenSTA timer and the OpenRCX extractor), Magic, KLayout and Netgen in a fixed order and stops if a check fails. Commercial flows have the same steps with different tools, named in each section and collected in a table in section 4.

2. The digital flow, step by step

Each step below says what is done, which files go in and come out, which tools do it, and what you look at before moving on. Tool names in the first sentence of “Tools” are what LibreLane runs for SKY130. Commands are short examples of the underlying tool, not complete scripts.

1. Specification

What happens
Decide what the chip must do and the numbers it must meet: functions, interfaces, clock frequency, power, area, pin list and supply voltages. Mixed-signal parts add accuracy, noise and speed targets for each analog block.
In → out
Product requirements → a written specification, a block diagram, a pin list, and a verification plan that says how each requirement will be tested.
Tools
Documents and spreadsheets; architecture models in Python, C or SystemVerilog when behavior needs exploring before any hardware is described.
You check
Every requirement is measurable, and every interface between blocks — voltage levels, timing, protocol — is written down (lesson 84).

2. RTL design and simulation

What happens
Describe the digital design as registers and the logic between them, in Verilog or SystemVerilog. Lint it, then simulate it against testbenches until it behaves as specified.
In → out
Specification → RTL source files, testbenches, simulation logs and waveforms.
Tools
Verilator (lint and fast simulation), Icarus Verilog (event-driven simulation), cocotb (testbenches written in Python), GTKWave (waveform viewer). Commercial: Synopsys VCS, Cadence Xcelium, Siemens Questa. LibreLane’s first step, Verilator.Lint, lints the RTL.
You check
Correct behavior for the tests that were run, and no lint warnings about unintended latches, width mismatches or multiple drivers (lesson 34).
verilator --lint-only -Wall counter.v
iverilog -o sim tb_counter.v counter.v && vvp sim

3. Synthesis

What happens
Translate the RTL into a netlist of standard cells from the target library. The tool infers registers and logic, optimizes the logic, and maps it onto real cells using their Liberty data, guided by timing constraints such as the clock period.
In → out
RTL + Liberty file + timing constraints (SDC) → gate-level netlist, a cell-area report, and a first timing report with estimated wires.
Tools
Yosys, which calls ABC for logic optimization and technology mapping; OpenSTA for the pre-layout timing check. Commercial: Synopsys Design Compiler or Fusion Compiler, Cadence Genus. LibreLane steps: Yosys.Synthesis, then OpenROAD.STAPrePNR.
You check
No unmapped cells and no latches you did not intend; total cell area; timing slack before layout (lesson 34, lesson 22).
yosys -p "read_verilog counter.v; synth -top counter; \
  dfflibmap -liberty sky130_fd_sc_hd__tt_025C_1v80.lib; \
  abc -liberty sky130_fd_sc_hd__tt_025C_1v80.lib; \
  write_verilog -noattr counter_netlist.v"

4. Floorplan and power grid

What happens
Fix the outline, create the rows of placement sites, place the I/O pins and any macros, insert well taps and endcaps, and build the power grid of rings, straps and rails.
In → out
Netlist + technology LEF and cell LEFs + floorplan settings → a layout database (DEF) holding the die area, rows, pins, macros, taps and power grid.
Tools
OpenROAD: initialize_floorplan, place_pins, macro placement, tapcell and pdngen. Commercial: Cadence Innovus, Synopsys IC Compiler II or Fusion Compiler. LibreLane steps: Floorplan, CutRows, TapEndcapInsertion, GeneratePDN, IOPlacement.
You check
Utilization and aspect ratio, pin positions against the neighboring blocks, and a fully connected power grid (lesson 55, lesson 14, lesson 48).
initialize_floorplan -die_area "0 0 300 300" -core_area "10 10 290 290" -site unithd
place_pins -hor_layers met3 -ver_layers met2
tapcell -distance <max_tap_spacing> -tapcell_master sky130_fd_sc_hd__tapvpwrvgnd_1 \
        -endcap_master sky130_fd_sc_hd__decap_3
pdngen

5. Placement

What happens
Put every standard cell on a legal site. Global placement spreads the cells to shorten wires and avoid congestion; detailed placement snaps them onto sites without overlaps. Along the way the tool repairs electrical-rule violations — slew, capacitance, fanout — by resizing cells and adding buffers.
In → out
Floorplanned database + netlist → placed database, with a netlist updated for the inserted buffers.
Tools
OpenROAD: global_placement, repair_design, detailed_placement. Commercial: Innovus, IC Compiler II. LibreLane steps: GlobalPlacement, RepairDesignPostGPL, DetailedPlacement, with a timing check (STAMidPNR) in between.
You check
Congestion, placement density, and timing with estimated wire parasitics (lesson 13, lesson 11, lesson 19, lesson 58).
global_placement -density 0.6
repair_design
detailed_placement

6. Clock-tree synthesis

What happens
Build a tree of clock buffers that delivers the clock to every flip-flop with controlled skew and slew. Then repair timing using real clock arrival times, which is when hold violations first appear.
In → out
Placed database + clock definitions from the SDC → database with clock buffers, and timing reports with propagated clocks.
Tools
OpenROAD: clock_tree_synthesis, then repair_timing. Commercial: Innovus (CCOpt), IC Compiler II. LibreLane steps: CTS, ResizerTimingPostCTS.
You check
Skew, insertion delay and clock slew; setup and hold slack with propagated clocks (lesson 35, lesson 26).
clock_tree_synthesis -root_buf sky130_fd_sc_hd__clkbuf_16 \
                     -buf_list {sky130_fd_sc_hd__clkbuf_4 sky130_fd_sc_hd__clkbuf_8}
set_propagated_clock [all_clocks]
repair_timing -hold

7. Routing

What happens
Draw every wire. Global routing assigns each net to a corridor of routing cells and exposes congestion. Detailed routing draws the actual wires and vias on the routing tracks while obeying every spacing rule. Antenna violations are repaired with diodes, and fill and decap cells close the remaining gaps in the rows.
In → out
Placed database with its clock tree → fully routed database.
Tools
OpenROAD: global_route, repair_antennas, detailed_route, filler_placement. Commercial: Innovus (NanoRoute), IC Compiler II (Zroute). LibreLane steps: GlobalRouting, RepairAntennas, DetailedRouting, FillInsertion.
You check
Zero routing violations, zero antenna violations, total wire length, and timing after routing (lesson 14, lesson 51, lesson 47, lesson 59).
global_route
repair_antennas sky130_fd_sc_hd__diode_2
detailed_route
filler_placement {sky130_fd_sc_hd__decap_* sky130_fd_sc_hd__fill_*}

8. Parasitic extraction and timing signoff

What happens
Compute the resistance and capacitance of every routed wire from its shape, then rerun static timing analysis with those values at every corner the project requires. A static voltage-drop analysis checks the power grid.
In → out
Routed database + extraction rules → SPEF. SPEF + netlist + one Liberty file per corner + SDC → timing reports.
Tools
OpenRCX (extract_parasitics, write_spef), OpenSTA (read_spef, report_checks), OpenROAD’s IR-drop analyzer (analyze_power_grid). Commercial: Synopsys StarRC and PrimeTime; Cadence Quantus, Tempus and Voltus; Ansys RedHawk. LibreLane steps: RCX, STAPostPNR, IRDropReport.
You check
Setup and hold slack at every corner, maximum slew and capacitance, and supply voltage drop (lesson 28, lesson 25, lesson 26, lesson 68).
extract_parasitics -ext_model_file <rcx_rules_file>
write_spef counter.spef
read_spef counter.spef
report_checks -path_delay min_max
analyze_power_grid -net VPWR

9. Physical verification

What happens
Write the final layout as GDS and prove that it can be manufactured and matches the netlist: design-rule checks on every shape, an XOR between GDS files written by two different tools, layout-versus-schematic comparison, and antenna checks. An equivalence check can also compare the final netlist with the RTL.
In → out
Routed database + cell layouts → final GDS, and a report from each check.
Tools
Magic and KLayout (GDS stream-out and DRC), KLayout (XOR), Magic (extracts a netlist from the layout) with Netgen (LVS), and Yosys EQY (equivalence; off by default in LibreLane). Commercial: Siemens Calibre, Cadence Pegasus, Synopsys IC Validator; Cadence Conformal or Synopsys Formality for equivalence. LibreLane steps: Magic.StreamOut, KLayout.StreamOut, KLayout.XOR, Magic.DRC, KLayout.DRC, Netgen.LVS.
You check
Zero DRC, LVS, XOR and antenna errors — or documented waivers — with timing already closed at every corner (lesson 62, lesson 51).
netgen -batch lvs "counter_extracted.spice counter" "counter_netlist.v counter" \
       sky130A_setup.tcl lvs_report.out

10. Tapeout

What happens
Add what the foundry and the shuttle require — metal fill, the seal ring, the shuttle’s own precheck — and hand over the GDS. The foundry makes masks and processes wafers; the dies are then tested, diced and packaged.
In → out
Final GDS → masks → wafers → packaged parts.
Tools
For a whole chip, LibreLane’s Chip flow adds pad-ring, seal-ring, filler and density steps; open_pdks also ships Magic-based fill and seal-ring scripts for SKY130. On a Caravel shuttle the harness supplies the ring, and you deliver the contents of user_project_wrapper, a 2920 × 3520 µm block. Mask preparation is done by the foundry.
You check
The precheck passes, and the pin list, supplies and bring-up plan are documented before the parts come back (lesson 2, lesson 5, lesson 6).

3. The analog flow, step by step

Analog and custom circuits are designed by hand, device by device. The steps mirror the digital flow, but a person makes each decision, and simulation — not a timing table — is the judge.

A1. Schematic

What happens
Choose devices from the PDK’s primitives, size them, and draw the circuit.
In → out
Block specification → a schematic and its SPICE netlist.
Tools
xschem with the SKY130 symbol library. Commercial: Cadence Virtuoso Schematic Editor.
You check
Device types and voltage ratings suit every node, and every bias and reference has a defined source (lesson 72, lesson 76).

A2. Simulation

What happens
Simulate the operating point, small-signal response, transient behavior and noise. Repeat across process corners, supply and temperature, and use Monte Carlo runs for mismatch.
In → out
Netlist + PDK device models + test benches → waveforms and measured performance against the specification.
Tools
ngspice or Xyce with the SKY130 models. Commercial: Cadence Spectre, Synopsys HSPICE and PrimeSim.
You check
Every specification met at every corner, with margin — including stability and startup, not only the nominal operating point (lesson 73, lesson 75).
ngspice -b bench.spice

A3. Layout

What happens
Draw the devices and wires polygon by polygon, placing matched devices symmetrically and keeping sensitive nets away from noisy ones.
In → out
Schematic → layout (GDS).
Tools
Magic, with its SKY130 device generators, or KLayout. Commercial: Cadence Virtuoso Layout Suite.
You check
Matching, current paths and wire widths, shielding and guard rings (lesson 78, lesson 83).

A4. Verification and post-layout simulation

What happens
Run design-rule checks, compare the layout with the schematic, extract the layout’s parasitic resistance and capacitance, and simulate again with them included.
In → out
Layout + schematic → DRC and LVS reports, an extracted SPICE netlist, and post-layout results.
Tools
Magic (DRC and extraction), KLayout (DRC), Netgen (LVS), ngspice (post-layout simulation). Commercial: Siemens Calibre, Cadence Quantus.
You check
Clean DRC and LVS, and the specification still met once parasitics are included (lesson 78).

A5. Views for integration

What happens
Package the block so the digital flow can use it: its layout, an abstract that shows only the outline, pins and blockages, and a model of its interface.
In → out
Verified layout → GDS, a LEF abstract, and a Liberty or behavioral Verilog model.
Tools
Magic writes the LEF abstract; the interface model is written by hand or characterized. The block is then placed as a macro in step 4 and checked again at the top level in steps 8 and 9.
You check
Pin names, supplies and timing in the model match the real block (lesson 84).

5. The flow is a loop, not a line

The figure shows one pass. Real projects go around several times, because each step reveals problems the previous one could only estimate. Typical loops:

  • Synthesis and constraints. If timing fails by a wide margin before layout, layout will not rescue it. Change the RTL — add a pipeline stage, simplify the logic — or correct the constraint.
  • Placement, clock tree and routing with timing repair. After each of these steps the flow reruns timing and lets the resizer swap cell sizes and insert buffers. LibreLane runs a timing check four times between placement and routing for this reason.
  • Routing and the floorplan. Congestion or routing violations that will not clear usually mean the floorplan is too dense: lower the utilization, move macros or pins, or adjust the power grid (lesson 55).
  • Signoff and late fixes. A small problem found at the end is fixed with an engineering change order: a few edited cells or wires instead of a full rerun (lesson 53).
  • Analog layout and simulation. If the extracted block misses its specification, change the layout first and the schematic second, then verify again.

The further back a fix reaches, the more it costs, so each step tries to catch what it can see: lint before simulation, pre-layout timing before placement, congestion before detailed routing.

6. Running the flow on SKY130

LibreLane reads a configuration file that names the design, its source files and its clock. A minimal one looks like this, in the style of the LibreLane documentation’s examples:

{
  "DESIGN_NAME": "counter",
  "VERILOG_FILES": "dir::counter.v",
  "CLOCK_PORT": "clk",
  "CLOCK_PERIOD": 10
}

Running librelane config.json starts the default flow, called Classic. It loads the SKY130 HD library from the installed PDK, runs 80 steps in a fixed order — the Classic Steps list in LibreLane 3.0.17, shown in Figure 2 — and writes each step’s outputs, logs and reports into its own folder inside a run directory. You can open the result of any run afterward, for example in KLayout with librelane --last-run --flow OpenInKLayout config.json.

Configuration variables switch steps on and off or tune them: RUN_EQY enables the equivalence check, RUN_ANTENNA_REPAIR controls diode insertion, and so on. The clock period is in nanoseconds, so the example asks for 100 MHz.

7. The PDK supplies the ingredients

The PDK (process design kit) turns a foundry process into files that tools can use. For SKY130, the open_pdks project builds an installed PDK; its default variant, sky130A, has local interconnect plus five metal layers. Inside are SPICE models for each transistor type and corner, design-rule and extraction decks, the high-density standard-cell library sky130_fd_sc_hd, the I/O library sky130_fd_io, and technology files for the router.

Names follow a pattern: sky130_fd_sc_hd__inv_1 is process sky130, foundry-provided (fd), standard cell (sc), high-density library (hd), cell inv, drive strength 1 (lesson 4 decodes the device names).

LEF stands for Library Exchange Format, DEF for Design Exchange Format, SDC for Synopsys Design Constraints, SPEF for Standard Parasitic Exchange Format, SPICE for Simulation Program with Integrated Circuit Emphasis, and GDSII (usually just GDS) for the Graphic Data System stream format. Liberty is a name rather than an acronym. The names are historical; what matters is the other columns. Each file is a view of the same design, and no single view contains everything. Mistakes happen when someone reads a fact from the wrong view — a pin rectangle in a LEF taken as a bond opening, for instance (lesson 67).

DRC (design-rule check)Does every shape obey the foundry’s width, spacing, enclosure and density rules?GDS against the rule deck9

Each check proves only what it compares. A clean LVS says the layout is wired as the netlist says; it says nothing about speed. A clean STA says the paths meet the stated constraints; it says nothing about whether the constraints describe the real environment (lesson 84).

Models are characterized at combinations of process, voltage and temperature — PVT — called corners. A name such as tt_025C_1v80 means typical-typical process (typical NMOS and typical PMOS), 25 °C, 1.80 V. ss is slow-slow, ff fast-fast, and sf and fs mix a slow device type with a fast one. Timing must close at every corner the project requires (lesson 22).

Check your understanding — which file would you open to find (a) the delay of nand2_1 at a 10 fF load, (b) where pin A of inv_1 is, (c) the width of inv_1’s NMOS, (d) whether two met1 shapes are too close together?

(a) The Liberty file at the corner you care about. (b) The cell LEF. (c) The SPICE netlist. (d) The layout (GDS), checked against the DRC rule deck — no single file states the answer until the check is run.

Check your understanding — does a clean LVS prove that the chip meets its timing?

No. LVS compares connectivity and devices. Timing needs STA with the right constraints and extracted parasitics, and the constraints must describe the real clocks and interfaces.

Check your understanding — after routing, one path misses setup by 50 ps. Which steps could you return to, from cheapest to most expensive?

First let timing repair resize or buffer the cells on that path and reroute them (steps 7 and 8). If that fails, improve the placement of that logic (step 5), then revisit the floorplan or pin positions (step 4). Last, change the RTL or the constraint — pipeline the path, or correct a requirement that was too strict (steps 2 and 3). Each step back costs more rework but can fix a larger problem.

Key takeaways

  • Digital flow: specification → RTL and simulation → synthesis → floorplan and power grid → placement → clock-tree synthesis → routing → extraction and timing → physical verification → tapeout.
  • For SKY130, LibreLane runs Verilator, Yosys, OpenROAD (with OpenSTA and OpenRCX), Magic, KLayout and Netgen; commercial flows use tools such as Design Compiler or Genus, Innovus or IC Compiler II, PrimeTime or Tempus, and Calibre.
  • Analog flow: schematic (xschem) → simulation (ngspice) → layout (Magic or KLayout) → DRC, LVS, extraction and re-simulation → GDS, LEF and a model for integration.
  • Every step reads the previous step’s files and writes new ones; a failure sends you back, and earlier fixes cost more.
  • Each file is one view: SPICE has transistors, Liberty has timing, LEF has outlines and pins, DEF has placement, GDS has polygons.
  • STA, DRC, LVS and PEX answer different questions; none replaces the others.
