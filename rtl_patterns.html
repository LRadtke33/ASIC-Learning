Lesson 33 / 84 · Part V, Digital implementation

RTL Patterns: FSMs, Handshakes, Resets & Lint

A 3-state traffic light mapped by Yosys 0.52 onto sky130_fd_sc_hd: binary encoding is 7 cells and 98.8448 µm²; explicit one-hot is 13 cells and 177.6704 µm². The one-hot reset bit that is 1 after reset maps to a dfstp_2 (async set), not a reset flop.

Where the numbers come from. Both machines were synthesised on 11 November 2026, America/Chicago, with Yosys 0.52 (fee39a3284c90249e1d9684cf6944ffbbcbb8f90) and ABC, against the same filtered Liberty used in lesson 44: the SKY130 HD tt_025C_1v80 table after LibreLane Classic 3.0.17’s default SYNTH_EXCLUDED_CELL_FILE (no_synth.cells) and PNR_EXCLUDED_CELL_FILE (drc_exclude.cells). The script is proc; flatten; opt; memory; opt; techmap; opt; dfflibmap; abc; clean; stat -liberty — the Yosys fsm pass was not run, so it did not recode the states. RTL, scripts, mapped netlists and stat excerpts are in labs/analysis_examples/rtl_patterns/. Areas are Yosys’s Liberty-based chip area, which matches this PDK’s LEF for the cells used. No STA was run: this lesson does not claim a delay for either encoding. Verilator lint on the same RTL used the box’s Verilator 5.032 (Debian); the Lab 6 SPM lint cited in section 8 used Verilator 5.044 inside LibreLane’s nix environment. Handshake and pipeline figures are teaching diagrams, not simulation waveforms.

What you will learn

  • Write a clocked FSM with a default next-state, a complete case, and an async-assert reset that maps onto SKY130 dfrtp / dfstp cells.
  • Compare binary and one-hot encodings by area on a real Yosys mapping, and see why a one-hot state that is 1 after reset becomes a set flop.
  • Use a valid/ready handshake and a stallable pipeline without inferring latches.
  • Read a Verilator lint report, including CASEINCOMPLETE, and the LibreLane lint metrics recorded on the SPM.

Why it matters

1. What this lesson is for

Part V is the digital implementation path: RTL, a clock tree, gating, power, CDC, scan, memories and datapath. Every later lesson assumes the source is a synchronous, fully assigned, reset-safe description. This lesson is those habits, anchored on a machine small enough to read in one sitting and actually mapped onto this PDK.

Two Verilog files describe the same 3-state traffic light (red → green → yellow → red), advanced by a one-cycle tick pulse. One uses a 2-bit binary state, the other an explicit 3-bit one-hot. Both use an asynchronous active-low reset to red. The question is not which style is “better” in the abstract — it is what Yosys puts down when the encoding is left as written, and how much area that costs on sky130_fd_sc_hd.

2. The machine, as written

Three states, one input pulse, a 2-bit light output (0 = red, 1 = green, 2 = yellow). A default arm returns an illegal state to red. The sequential process is the only place that assigns state; next-state and output logic are combinational and complete.

// Binary encoding. One-hot is the same machine with
// S_RED = 3'b001, S_GREEN = 3'b010, S_YELLOW = 3'b100
// and a 3-bit state register.
localparam [1:0] S_RED = 2'd0, S_GREEN = 2'd1, S_YELLOW = 2'd2;
reg [1:0] state, next_state;

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) state <= S_RED;
    else        state <= next_state;
end

always @* begin
    next_state = state;                 // default: hold
    case (state)
        S_RED:    if (tick) next_state = S_GREEN;
        S_GREEN:  if (tick) next_state = S_YELLOW;
        S_YELLOW: if (tick) next_state = S_RED;
        default:            next_state = S_RED;
    endcase
end

The default assignment before the case is what stops a latch: every path assigns next_state. The default arm inside the case is a safety net for a corrupted state, not a substitute for that assignment. A 3-state machine cannot form a perfect Gray-code cycle — one of the three edges would flip two bits — so Gray is not compared here.

3. What Yosys actually mapped

On the filtered Liberty, dfrtp_1 and dfstp_1 are on no_synth.cells, so the mapper used the next legal drive: dfrtp_2 and dfstp_2. Each of those cells is 26.2752 µm² in this PDK’s LEF (9.66 × 2.72 µm). Yosys’s sequential-area line is exact integer multiples of that number.

Encoding, as writtenCellsFlip-flopsSequential area (µm²)Total area (µm²)
Binary (traffic_bin)72 × dfrtp_252.5504 (53.16%)98.8448
One-hot (traffic_oh)132 × dfrtp_2 + 1 × dfstp_278.8256 (44.37%)177.6704

One-hot is 1.80× the area of binary on this machine (177.6704 / 98.8448). It uses one more flop — three one-hot bits versus two binary bits — and more combinational logic to decode a 3-bit unique-hot vector. The interesting cell is the third flop: S_RED = 3'b001, so after reset state[0] must be 1. Yosys mapped that bit to sky130_fd_sc_hd__dfstp_2, an async-set flop whose SET_B pin is tied to rst_n. The other two bits reset to 0 and are ordinary dfrtp_2. That is the library doing what the RTL asked, not a bug.

Binary mapped to 2 × dfrtp_2 plus a21oi_2, two and2b_2, o21a_2 and mux2_1. The mapped Verilog is in the analysis folder and is short enough to read: state[0] and state[1] are the two flop outputs; the light bits are combinational functions of those Q pins.

One-hot is often recommended for “faster” next-state logic, because a state test is a single bit. On a 3-state machine that advantage, if it exists, is a timing claim, and this run did not measure timing. Use the area numbers; do not infer a frequency from them. For a machine with many states, flop area grows linearly with one-hot and only with the log of the state count for binary — that scaling is the usual reason to pick binary for a large FSM, and it is a reasoning argument, not a second measurement.

4. Reset, and which flop you get

The sensitivity list always @(posedge clk or negedge rst_n) is an asynchronous assert: when rst_n falls, the flop is forced without waiting for a clock edge. SKY130 HD has dedicated cells for that:

Cell (legal after exclusion: drive _2)LEF size (µm)LEF area (µm²)Job
dfxtp_2 (no async set/reset)7.82 × 2.7221.2704Plain D-flop; a sync reset is extra mux logic in front of D
dfrtp_2 (async reset, Q → 0)9.66 × 2.7226.2752What the binary machine used for both bits
dfstp_2 (async set, Q → 1)9.66 × 2.7226.2752What one-hot used for the bit that is 1 in S_RED

The _1 drives exist in the LEF (dfrtp_1 is 9.2 × 2.72 = 25.0240 µm²) but are on LibreLane’s no_synth.cells, so a default flow will not pick them — the same exclusion that lesson 44 applied to the adder and multiplier. Areas in the table are LEF SIZE, not a second synthesis of a synchronous-reset FSM.

Asynchronous assert is convenient; asynchronous release is not. If rst_n rises near a clock edge, two flops can leave reset on different cycles. The usual pattern is async assert, synchronous release: two flops in series, clocked, with async reset on both, the first’s D tied high, the second’s Q used as the local released reset. That synchroniser is a CDC topic — lesson 39 — and is not re-derived here.

5. Valid / ready

A datapath block that cannot be back-pressured will drop or overwrite a beat. The usual two-wire contract is: the sender raises valid and holds data stable; the receiver raises ready when it can accept; a transfer occurs in the cycle where both are 1. Either side may stall by deasserting its wire. This is a teaching diagram, not a simulated waveform.

A common bug is to compute ready from a registered full-flag that itself depends on a transfer in the same cycle, or to drop valid the instant the sender wants to move on, before the receiver has accepted. The safe sender rule: once valid is raised, hold valid and data until a cycle with ready.

6. Pipelines and stalls

A pipeline is a chain of valid/ready stages. Each stage registers data and a valid bit; its ready goes backward and is typically combinational from the next stage’s ready or from a local “not full.” A stall freezes the stage that cannot move and, if the handshake is correct, back-pressures the stages behind it so that no beat is lost and no stage overwrites a word it has not handed on.

7. Counters, parameters, and style that maps

A counter is an FSM with a regular next-state. Prefer a localparam width and a comparison against a named limit over a magic number, and reset it with the same async-assert convention as the traffic light. For a one-hot ring, the same dfstp observation applies: the bit that is 1 after reset is a set flop.

Parameterise widths with parameter or localparam (parameter WIDTH = 8) so a parent can instantiate #(.WIDTH(32)). Generate blocks are appropriate for repeated structure; they are not a way to hide incomplete assignments. Do not use initial to reset synthesizable state — simulators will, silicon will not (unless a tool happens to treat it as a hint, which you must not rely on). Do not use #delay in RTL that is going to a library: Yosys will ignore or reject it, and LibreLane’s lint has a dedicated metric for timing constructs.

8. Lint, and the pitfalls it is for

Two Verilator runs sit behind this section, and they are not the same binary.

The traffic-light RTL, Verilator 5.032 (Debian, this box). verilator --lint-only -Wall on traffic_bin.v completed with a clean report — no warnings. The same command on a deliberately broken companion, latch_pitfall.v, which assigns next_state only for states 0 and 1 and only when tick is 1, reported:

%Warning-CASEINCOMPLETE: latch_pitfall.v:4:9: Case values
    incompletely covered (example pattern 0x2)
%Error: Exiting due to 1 warning(s)

With -Wall, Verilator 5.032 treats that warning as fatal. The uncovered pattern is state 2 — exactly the arm the good FSM fills. An incomplete case in a combinational block is how a latch is inferred: the signal keeps its old value when no arm assigns it. Verilator named the coverage hole rather than the word “latch”; Yosys would then implement that hole as a latch if you mapped the bad file.

The Lab 6 SPM, Verilator 5.044, inside LibreLane 3.0.17. Step 01-verilator-lint of run RUN_2026-11-11_16-09-06 reported a clean log. The four LibreLane lint metrics, on steps 01–04, were all zero: design__lint_error__count, design__lint_timing_construct__count, design__lint_warning__count, and design__lint_inferred_latch__count. That is a recorded result on the bundled multiplier, not a claim about every design.

Why did the one-hot machine get a dfstp_2 as well as two dfrtp_2?

The reset state is 3'b001. The bit that must be 1 after reset is an async-set flop (dfstp_2, SET_B tied to rst_n). The bits that must be 0 are async-reset flops (dfrtp_2). Yosys mapped what the encoding asked for. The sequential area is 3 × 26.2752 = 78.8256 µm².

Is one-hot faster than binary on this traffic light?

This lesson does not say. The recorded facts are area (98.8448 vs 177.6704 µm²) and cell counts (7 vs 13). No STA was run. A timing claim would need a clock constraint and a report, as in lesson 34 or lesson 45.

Verilator reported CASEINCOMPLETE on the pitfall file, not the word “latch.” Is that file still going to infer a latch?

Yes, if you synthesise it. The uncovered encoding is state 2, and the arms that do exist only assign when tick is 1, so next_state is not assigned on every path. Verilator 5.032 named the coverage hole. Yosys would implement the unassigned path as a latch. The good FSM avoids this with a default assignment and a complete case.
