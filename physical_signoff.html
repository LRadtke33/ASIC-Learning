Physical Verification Signoff

Magic and KLayout DRC, a GDS XOR, Netgen LVS, and a manufacturability report — recorded on a clean SPM and on an inverter with injected errors. Antenna is in lesson 51; this lesson links to it.

Where the numbers come from. The clean SPM results are LibreLane 3.0.17 run RUN_2026-11-11_16-09-06 (FP_CORE_UTIL 45), steps Magic.StreamOut through Misc.ReportManufacturability, on 11 November 2026, America/Chicago. Tools: Magic 8.3.623, KLayout with sky130A_mr.drc (257 rules in the JSON report), Netgen with the PDK sky130A_setup.tcl. The injected DRC and LVS cases were run on a tap–inv_1–tap row and on extracted sky130_fd_sc_hd__inv_1, with the same Magic, KLayout and Netgen, and are the subject of Lab 7. Antenna ratios, diode insertion and the process physics are lesson 51 and are not repeated here. Density limits are lesson 61.

What you will learn

  • Why a flow runs two DRC engines and XORs two GDS files, and how to read a rule ID such as met1.2.
  • Read a Netgen LVS report: a unique match, a short, and a swapped pin, from actually extracted netlists.
  • Place antenna and density in the signoff list without repeating those lessons.
  • Walk the clean SPM signoff: Magic COUNT 0, KLayout all-zero, XOR 0, LVS unique match, manufacturability Passed.

Why it matters
A chip can meet timing and still be illegal to manufacture, or be legal and not match the netlist. Signoff is the last check that the GDS is both.

1. What “signoff” means here

After the route is DRC-clean in the router’s own checker and STA has closed, the flow still has to prove three things about the streamed GDS: it obeys the foundry’s geometry rules (DRC), it matches the netlist (LVS), and two independent streamers drew the same shapes (XOR). Antenna and density are part of that list; they have their own lessons. LibreLane runs this sequence after STAPostPNR.

The 45% SPM finished 80 of 80 steps. IR-drop was configured (RUN_IRDROP_REPORT was true) but was not executed in this folder, because the signoff resume started at Magic.StreamOut — the same fact as lesson 8. A later OpenROAD run on this final/, in lesson 63, measured 132 µV worst VPWR drop at nom_tt. Yosys EQY was gated off (False). Those were configuration choices, not failures. Setup, hold, slew and capacitance checkers reported no violations, consistent with lesson 45.

2. Why two DRC engines

Magic and KLayout implement the SKY130 rules independently. A single engine can have a false clean or a false error; agreement is stronger evidence than either report alone. They also present the same rule differently, which is useful when you debug. Lab 7 injected a 0.05 µm metal1 gap (the rule is 0.14 µm) into an otherwise clean tap–inv_1–tap row:

Magic’s message is “Metal1 spacing < 0.14um (met1.2)” with four boxes (the gap and the facing edges of the rail). KLayout’s JSON and lyrdb use the identifier m1.2, description “min. m1 spacing : 0.14um”, and one edge-pair: (0.86,2.43;1.36,2.43)/(1.491,2.48;0.729,2.48). Same violation, same unit, different marker count. The clean row was COUNT: 0 in Magic and 0 items in KLayout. On the full SPM, Magic printed [INFO] COUNT: 0 and KLayout’s 257-rule JSON had every value 0, including m1.2, m1.1, m1.6 and the licon.* family.

An isolated inv_1, with no neighbouring taps, is not DRC-clean: Magic reported nwell.4 (nwell without a metal-connected N+ tap), LU.2 and LU.3 (diffusion-to-tap distance). That is a real SKY130 rule, and it is why well taps (lesson 48) exist. Putting a tap_1 on each side of the inverter cleared those five errors. The lab starts from that row, not from a cell in mid-air.

3. Mapping rule IDs

KLayout’s lyrdb lists a description for every rule it checked. A selection used in this lesson and in Lab 7, all with count 0 on the clean SPM:

When a report gives only an ID, look the ID up in the lyrdb description — or in Magic’s English sentence, which includes the ID in parentheses. Do not assume that “m1.2” and “met1.2” are different rules; they are the same spacing check with two spellings.

4. XOR of two GDS files

LibreLane writes GDS twice: Magic.StreamOut produced spm.gds at 702,348 bytes, KLayout.StreamOut produced spm.klayout.gds at 386,238 bytes. The files are different sizes because the streamers encode hierarchy and cells differently; they are not automatically the same geometry. KLayout.XOR boolean-compares named layers and reported, for every layer including 78/44, 81/4, 83/44, 93/44, 94/20 and 95/20:

XOR differences: 0
...
Total XOR differences: 0
%OL_METRIC_I design__xor_difference__count 0

A non-zero XOR means the two tools disagreed about a shape: a missing via, a shifted polygon, a layer-map error. It is not a foundry DRC. Fix the streamout, not the router, until XOR is zero — or document a waiver if a known encoding difference is harmless and understood. Checker.IllegalOverlap, a separate geometry check, was also 0 (magic__illegal_overlap__count: 0).

5. LVS: shorts, opens, pins and body ties

Magic extracts a SPICE netlist from the layout; Netgen compares it with the reference netlist. On the SPM, both circuits had 328 devices and 361 nets, pin lists were equivalent, and the report ended:

Device classes spm and spm are equivalent.

Final result: Circuits match uniquely.

Checker.LVS agreed: every design__lvs_*__count metric was 0. That is the result you want at tapeout.

Lab 7 ran the same tools on sky130_fd_sc_hd__inv_1, comparing an extracted layout against the library subcircuit (one nfet 0.65/0.15, one pfet_hvt 1.0/0.15, pins A, Y, VGND, VNB, VPB, VPWR):

CaseExtracted netlistNetgen final result
Clean cell2 devices, 6 nets, pins A and Y in the usual placesNetlists match uniquely. Circuits match uniquely.
A shorted to Y (a locali bridge)Pin A disappears; both gates are on Y. Nets: 5 vs 6, MismatchNetlists do not match. Final result: Top level cell failed pin matching.
Pins A and Y name-swapped2 devices, 6 nets — same topologyNetlists match uniquely, but pins Y | A **Mismatch** and A | Y **Mismatch**. Final result: Top level cell failed pin matching.

The pin-swap is the teaching case: a clean device count does not mean the cell is right. Netgen will tell you the graph matches and the pins do not. A missing body tie (VNB or VPB unconnected) shows up as a pin or net mismatch of the same family; the clean extract includes both body terminals, and they matched the library. Opens — a missing contact, a broken rail — reduce the net count or split a net; they were not injected in Lab 7, and are not claimed here.

6. Antenna — see lesson 51

Antenna checking belongs in this signoff list, but the ratio, the accumulated charge, the diode, and the SKY130 rules are already taught in lesson 51. This run’s result, and nothing more, is: antenna__violating__nets: 0, antenna__violating__pins: 0, antenna_diodes_count: 0, route__antenna_violation__count: 0, and the manufacturability report’s Antenna line “Passed”. RUN_ANTENNA_REPAIR was enabled; no diodes were needed. If a later design fails this check, go to lesson 51 for the diagnosis, not to a second copy of that material.

7. Density — see lesson 61

Foundry density rules (metal fill for planarization, cell fill for row continuity) are lesson 61. The 45% SPM’s final fill is in the placement metrics: 803 fill cells, area 2,667.56 µm², final instance utilization 0.630246. This signoff lesson does not re-derive those limits. You still need a density check on a real tapeout; this flow’s manufacturability report folded the pass/fail it ran into DRC / LVS / Antenna, all Passed.

8. Reading a failure

A practical order, used in Lab 7 and on the SPM reports:

  1. If XOR is non-zero, fix streamout before chasing DRC that may be a drawing artefact.
  2. If DRC is non-zero, map the rule ID to a description, open the marker, and decide whether the geometry is yours (a drawn error, a routing leftover) or a context error (a cell without taps, a rule that applies at the chip edge).
  3. If LVS fails, read the mismatch class: net count (short or open), device count (missing or extra device), or pin list (swap, missing body tie, unconnected port). The Lab 7 short and pin-swap reports are the templates.
  4. If antenna fails, lesson 51.
  5. If only density fails, lesson 61.

The SPM at 45% never needed that list: every check in Figure 1 passed, and final/gds/spm.gds is the streamed result. Lab 6 is the RTL-to-GDS path that produced it; Lab 7 is the debug path on a cell you can break on purpose.

KLayout reported one m1.2 item and Magic reported four boxes. Which tool is wrong?

Neither, on this evidence. They flagged the same 0.05 µm gap against the same 0.14 µm rule. Magic listed four boxes (the injected rectangle and segments of the facing rail). KLayout listed one edge-pair joining those facing edges. A count comparison without looking at the markers would have been misleading; the descriptions and coordinates agree.
