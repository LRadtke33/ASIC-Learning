DFT Beyond Scan: Faults, ATPG, BIST and JTAG

What a scan chain is for: fault models, test time, at-speed capture, memory and logic BIST, and the IEEE 1149.1 TAP. The chain itself is lesson 40.

Where the numbers come from. Scan-cell and flop areas are from the sky130_fd_sc_hd LEF in this course’s PDK (ciel 8afc8346a57fe1ab7934ba5a6056ea8b43078e71): sdfxtp_1 is 9.660 × 2.720 µm (26.2752 µm²), dfxtp_1 is 7.360 × 2.720 µm (20.0192 µm²). The 64 flip-flops in the test-time example are the 64 dfrtp_2 of the Lab 6 SPM; the pattern count in that example is assumed and labelled. Fault-model figures, the TAP machine and the March C− sequence are standard teaching material, not a tool run. OpenROAD DFT and a stuck-at ATPG were not run for this lesson and are not quoted as results.

What you will learn

  • Distinguish stuck-at, transition and bridging faults, and say what “coverage” means for yield.
  • Estimate shift-test time from chain length, pattern count and shift frequency.
  • Describe at-speed launch-on-capture, scan compression, logic BIST and March memory BIST.
  • Read an IEEE 1149.1 TAP and place it next to, not instead of, the core scan chain.

Where this fits · the flow map is lesson 8

In the flow
After the scan chain (lesson 40), before a timed path is closed and before memories are tested. ATPG and BIST patterns are generated after the netlist exists; they are not a LibreLane Classic step on the SPM run.
Tools
OpenROAD has a dft command set (set_dft_config, scan_replace, execute_dft_plan, scan_opt). Commercial: TestMAX, Tessent, Modus. JTAG insertion is a separate TAP tool. None of those tools was run for the figures below.
Why it matters
A chip that is DRC-clean and meets timing can still be untestable. Test time and coverage decide whether manufacturing can find the defects you care about.

1. The chain is the access path, not the test

Lesson 40 is about putting SKY130 scan flops (sdfxtp, sdfrtp) in a shift register and paying for that in area and in the timing of D versus SCD. This lesson is what you do with that path: you shift in a pattern, capture the circuit’s response, and shift the response out, many times, until the faults you modelled have been observed — or you stop and report the coverage you reached.

2. Fault models

A stuck-at fault says a node is 0 or 1 and will not move. A single-stuck-at test set is the workhorse of production test; it also catches a large fraction of opens and shorts it does not name. A transition (delay) fault says a node is slow to rise or slow to fall: you need a launch vector, a capture edge at the rated period, and a scan-out. Bridging faults short two nodes; the behaviour depends on the drivers, so the model is heavier. IDDQ (quiescent current) testing looks for elevated supply current from a short, and is mentioned here only as a complement — SKY130 leakage at 1.8 V is not measured in this lesson.

Coverage is the fraction of modelled faults that a pattern set detects. Yield and DPPM (defective parts per million) depend on the defect level that escapes, often written as a function of yield and of coverage (the Williams–Brown relation is the usual textbook form). That relation is a model, not a measurement from this PDK, and is not tabulated here.

3. Test time

For one serial scan chain, a useful first estimate is

T ≈ (Nff + 1) × Npat / fshift

where Nff is the chain length, Npat is the number of patterns (each pattern is shifted in, captured, and shifted out; the “+ 1” accounts for shifting the last response out), and fshift is the scan-shift clock, often slower than the functional clock.

Worked example, labelled as a calculation. The Lab 6 SPM has 64 flip-flops. If an ATPG tool produced 200 stuck-at patterns (that count is assumed, not generated) and you shifted at 10 MHz:

T ≈ (64 + 1) × 200 / (10 × 106) = 1.30 ms

A 10-million-flop SoC at the same pattern count and shift rate would need about 200 seconds — which is why compression, multiple chains and at-speed only on a subset of patterns exist. Scan compression (an on-chip decompressor on TDI and a compactor on TDO) cuts shifted bits by a ratio that depends on the codec; no compression ratio was measured here.

4. At-speed launch

A stuck-at capture can use a slow scan clock. A transition-fault test must launch and capture with a functional-period gap. Two standard ways:

  • Launch-on-capture (LOC, “broadside”): the launch is a functional response to the shifted pattern; the next edge captures. The launch path is a functional path, which is what you wanted to test.
  • Launch-on-shift (LOS, “skewed load”): the last shift edge is the launch, so the scan-enable must change in a fraction of a cycle — a tight constraint on the scan-enable tree.

SKY130 scan cells such as sdfxtp_1 (area 26.2752 µm² from the LEF, versus 20.0192 µm² for dfxtp_1) and sdfrtp (with reset) are the flops those tests walk through. Clock-gate cells used around scan include sdlclkp. Pin-level detail is in lesson 40.

5. BIST and March C−

Logic BIST generates patterns on chip (often an LFSR) and compact the signature (often a MISR), so the tester only starts the test and reads a pass/fail. Memory BIST runs a March algorithm through an SRAM. A widely used sequence is March C−:

ElementOperationWhat it is looking for
⇓ (w0)Write 0, address downInitialise
⇑ (r0, w1)Read 0, write 1, address upStuck-at, some transitions, addressing
⇑ (r1, w0)Read 1, write 0, address upThe opposite transition
⇓ (r0, w1)Read 0, write 1, address downCoupling in the other direction
⇓ (r1, w0)Read 1, write 0, address downCoupling, opposite data
⇑ (r0)Read 0, address upFinal check

That table is the standard March C− algorithm, not a run on the OpenRAM macro of the next lesson. A memory BIST controller walks this sequence (or a variant) at every address, at a frequency the compiler’s Liberty will support. The 1 kB OpenRAM in this PDK, and what its ports are, is lesson 43.

6. JTAG and the TAP

JTAG (IEEE 1149.1) is a four- or five-wire port (TCK, TMS, TDI, TDO, optional TRST) that talks to a TAP controller. It is how a board tests interconnect (boundary scan), how many chips are identified (IDCODE), and often how you start an on-chip BIST or access a debug register. It is not a substitute for the core scan chain: boundary-scan cells wrap the pads; the core chain of lesson 40 wraps the flops. A production program typically uses both.

7. What this course has not run

OpenROAD’s DFT commands can replace flops with scan cells and stitch chains; a separate ATPG tool (for example Fault) would then quote a coverage number. Those steps were not run on the SPM, and no coverage-versus-pattern curve is shown. If you add that experiment later, the honest report is the tool’s coverage, the pattern count, and the chain length, from which the formula in section 3 gives a time you can check against the tester.

A design has 4,000 flops, four equal scan chains, 800 patterns, and a 25 MHz shift clock. About how long is the stuck-at shift test?

Each chain is 1,000 flops. T ≈ (1,000 + 1) × 800 / (25 × 106) ≈ 32 ms. The four chains shift in parallel, so you use the length of one chain, not the total flop count. This is the same formula as section 3, with assumed numbers; it is not a tester measurement.
