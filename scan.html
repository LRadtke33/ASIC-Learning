Lesson 40 / 84 · Part V, Digital implementation

Scan

A scan flop is the same storage, with a second data pin. A test mode shifts a pattern in through that pin, and the chip's own logic never has to do it.

Where the numbers come from. sdfxtp_1 size, pins, and antenna are the LEF. The 32 transistors are the schematic spice. Function, caps, and the constraint cells are tt_025C_1v80. The plain flop is lesson 20.

What you will learn

  • Explain how a scan flop adds a second data input (SCD) selected by SCE.
  • Compare the scan flop sdfxtp_1 with dfxtp_1 in area, transistor count and setup time.
  • Draw a shift/capture sequence and compute test time from chain length, pattern count and shift frequency.
  • Name the OpenROAD dft commands and why LibreLane’s default flow does not run them.
  • Explain shift-path hold, lockup latches, and why test mode can be the noisiest mode.

Where this fits · the flow map is lesson 8

In the flow
Scan flops are inserted during or just after step 3, synthesis; test patterns are generated once the netlist is final.
Tools
Commercial: Synopsys DFT Compiler and TestMAX, Cadence Modus, Siemens Tessent. Open source: the OpenROAD dft module (scan_replace, execute_dft_plan, scan_opt), and the Fault toolchain for ATPG and JTAG insertion.
Why it matters
Scan is how production test finds manufacturing defects in every chip.

Verified source. The mux function, all quoted constraint entries, LEF dimensions and 32-device count were checked in the archived sdfxtp_1 files at HD revision ac7fb61f06e6. These cells do not by themselves establish test coverage.

1. Two data pins, one clock

A production test wants to set every flop to a known value and read every flop back, without depending on the logic between them. Scan does that by giving the flop a second input and a select. In mission mode the flop takes D. In scan mode it takes the scan data from the previous flop, and the flops form one long shift register.

The foundry note on the HD library says latches and flip-flops have scan equivalents. The scan equivalent of the positive-edge flop dfxtp_1 is sdfxtp_1.

2. Twenty-one sites, thirty-two transistors

sdfxtp_1 is class CORE, site unithd, SIZE 9.660 BY 2.720. That is 21 sites. Area 26.2752 µm². dfxtp_1 is 16 sites and 24 transistors. sdfxtp_2 is 10.12 × 2.72 µm, 22 sites. sdfxtp_4 is 11.04 × 2.72 µm, 24 sites. Timing below is only sdfxtp_1.

The schematic has 32 MOSFETs, every one l=150000u, which evaluates to 0.15 in this subcircuit wrapper’s micrometer geometry convention. Preserve the model wrapper and simulator scaling when reproducing the simulation. Sixteen are nfet_01v8 and sixteen are pfet_01v8_hvt. Pins are D, SCD, SCE, CLK, and Q, plus the rails. CLK is USE CLOCK.

4. The chain is Q of one flop into SCD of the next

With SCE=1, Q feeds the next flop’s SCD, forming a shift register. With SCE=0, each flop captures its functional D. A simple stuck-at pattern uses a capture pulse; transition-delay testing may use a launch/capture sequence and different enable timing. Scan architecture and test protocol determine the required clocks.

Scan provides controllability and observability for test generation. In a stuck-at example, ATPG (automatic test pattern generation) selects a pattern that excites a fault and propagates its effect to an observed flop. A wrong output bit means a test response mismatch; it does not uniquely identify the faulty net. At-speed scan can also test transition and path-delay behavior, and many physical defects require other fault models or tests.

In the open SKY130 flow. Scan insertion is a design-for-test step run during or just after synthesis: the tool swaps ordinary flops for scan flops and stitches the chain, and automatic test pattern generation later produces the test vectors. Commercial tools are Synopsys DFT Compiler and TestMAX, Cadence Modus and Siemens Tessent. Fault is an open-source design-for-test toolchain built around Yosys; LibreLane’s default flow has no scan step.

5. Shift loads the chain; capture uses the functional path

A typical stuck-at protocol has three phases. Shift drives SCE high and clocks the chain until every flop holds a chosen bit. Capture drives SCE low and applies one (sometimes two) clock pulse so each flop samples its functional D, which is the result of the combinational logic under the shifted-in pattern. Unload drives SCE high again and shifts the captured bits out, often overlapping the load of the next pattern. Transition-delay and path-delay tests use a launch/capture pair at-speed; the shift clock is usually slower.

The tester sees only the scan-in and scan-out pins (and the clocks and SCE). Everything between those pins is a shift register during shift, and is the functional circuit during capture. ATPG chooses the shifted-in bits so that a modelled fault, if present, changes a captured bit. A mismatch on scan-out says the test failed; it does not, by itself, name the defective net.

6. OpenROAD inserts and stitches the chains

OpenROAD’s dft module is the open-source insertion path that matches the Tools list at the top of this lesson. The documented command sequence is:

  1. set_dft_config — optional limits such as -max_length (bits per chain), -max_chains, and -clock_mixing (no_mix keeps one clock and edge per chain; clock_mix may mix clocks, stitching falling-edge cells before rising-edge cells).
  2. scan_replace — swap ordinary flops for scan equivalents. This changes cell area, so it runs before placement.
  3. Global placement, then report_dft_plan -verbose — a preview that does not modify the design. Use it to iterate the configuration.
  4. execute_dft_plan — architect the chains and connect them, after placement, in a way that aims to reduce wirelength.
  5. scan_opt — reorder cells inside each chain (and optionally -rebalance_chains between chains of the same clock and edge) using the current placement, then rewire. Chains with unplaced cells are skipped. Falling-edge cells stay ahead of rising-edge cells, and the cell that drives scan-out stays last.

Those are OpenROAD commands. LibreLane Classic 3.0.17’s default flow has no DFT step: it will not call scan_replace for you. If you want scan in that flow, you run the commands yourself (or through a wrapper) at the points above. Commercial tools and the Fault toolchain remain the usual sources of ATPG patterns and of JTAG / test-access structures that OpenROAD’s dft module does not generate.

In the open SKY130 flow. The HD library already contains the scan equivalents (sdfxtp, sdfrtp, and the other s* flops). Insertion is a netlist transformation plus stitching, not a new foundry cell. Fault (built around Yosys) is an open-source ATPG and JTAG path. This lesson does not run ATPG, and it does not claim a coverage number for any design.

7. Test time, area and shift power

Test time for a full-scan campaign is arithmetic on the chain architecture, the pattern count and the shift clock — not a process speed rating. If unloading the previous response overlaps loading the next pattern, a useful estimate is

T ≈ Npatterns × (Lchain + Ncapture) / fshift

where Lchain is the longest chain (the tester is limited by the slowest chain) and Ncapture is the number of capture clocks per pattern (one for a basic stuck-at sequence).

Worked example. A block has 2,000 scan flops and 500 patterns, shifted at 25 MHz, with one capture clock and overlapping unload/load.

ArchitectureLongest chainCycles per patternTest time
One chain2,0002,001500 × 2,001 / 25 MHz = 40.02 ms
Four chains of 500500501500 × 501 / 25 MHz = 10.02 ms

Four chains cut test time by about four, at the cost of four scan-in pins and four scan-out pins (or an equivalent test-access compressor). If load and unload do not overlap, each pattern pays about two chain lengths, and the four-chain time becomes 500 × 1,001 / 25 MHz = 20.02 ms. Loading a 1,000-bit chain at 10 MHz takes 100 µs before capture and unload. None of these frequencies is a SKY130 rating; shift rate is set by hold, power and the tester.

Area. Replacing every dfxtp_1 (16 sites, 20.0192 µm²) with sdfxtp_1 (21 sites, 26.2752 µm²) grows those flop cells by 21/16 = 31.25%. For 2,000 such replacements the extra cell area is 2,000 × 6.256 µm² = 12,512 µm². That is only the standard-cell footprints. Scan routing, any lockup cells, and extra clock-tree load add more. It is not a 31% growth of the whole die.

Shift power. Random patterns can toggle about half the scan bits on every shift edge, and every scan flop is clocked at fshift. Functional activity is often much lower, which is why section 8’s warning about supply droop is a power problem as well as a test-quality problem. The clock-power lesson treats C·V²·f for a clock pin; during shift you pay that term on the whole chain, plus the data-activity term on every Q→SCD net.

Check your understanding — four chains of 500 at 10 MHz, 200 patterns, overlapping unload, one capture clock: how long is the test?

Lchain = 500, so T = 200 × (500 + 1) / 10 MHz = 200 × 501 / 107 = 10.02 ms. The four chains run in parallel; the length of the longest chain, not the 2,000-bit total, sets the time. A slower shift clock lengthens the test in proportion.

8. Hold, lockup latches, and a noisy test mode

A slow shift clock relaxes shift setup and reduces shift power, but it does not cure hold. The Q→SCD path is a short route between adjacent flops, and the hold figures in section 3 are already negative at a 0.01 ns edge: the data is allowed to change slightly before the clock. Clock skew on the scan path can still create a hold violation. That check uses the actual scan-clock arrival times, in the shift mode where SCE is held high. Lesson 42 works a Q→SCD hold check on these same cells.

Scan can toggle more state than normal operation, causing supply droop and substrate noise. Constrain the shift frequency, simultaneous switching, and analog power states. Clock-domain partitioning of chains is the other standard remedy beside lockup cells: do not stitch unlike clocks onto one chain if you can give each domain its own chain.

ModeWhat must be checked
ShiftScan-enable timing, short-path hold (with actual scan-clock skew), chain integrity, lockup or domain partitioning, shift power
CaptureFunctional or at-speed timing, clock gating, observation of fault effects
Analog testSafe mux settings, references and supplies, test-bus loading and isolation
Checkpoint: is passing scan sufficient to approve an ADC?

No. Scan checks selected digital fault models. Converter offset, noise, linearity, reference behavior and analog defects need their own analog and mixed-signal tests (lesson 80, lesson 84).

Check your understanding — why is the falling-D setup time of sdfxtp_1 about twice that of dfxtp_1?

The scan flop selects between D and SCD before the master latch, and that extra stage adds delay to the data path, so data must arrive earlier: 0.202 ns against 0.103 ns at 0.01 ns edges in the HD tables.

Lesson 42 puts these scan flops into a timed path: it compares the dfxtp and sdfxtp arcs, checks the scan-enable constraints and works the hold check in shift mode.

Key takeaways

  • Scan adds a second data pin and a select, so test can shift a pattern through the flops.
  • sdfxtp_1 is 21 sites and 32 transistors. dfxtp_1 is 16 sites and 24. Replacing one with the other grows that cell’s area by 31.25%.
  • With SCE low, the flop takes D. With SCE high, it takes SCD.
  • At 0.01 ns edges, falling-D setup is 0.202 ns on the scan flop and 0.103 ns on dfxtp_1.
  • A stuck-at sequence is shift, capture, unload. Test time is set by the longest chain, the pattern count and the shift clock.
  • OpenROAD dft uses scan_replace (before placement), execute_dft_plan (after), and scan_opt. LibreLane Classic’s default flow does not run them.
  • Hold is negative in the HD tables. A longer period does not fix hold. Lockup latches or per-domain chains protect scan stitches that cross clocks.
  • Shift can be the noisiest, most power-hungry mode on the chip.
