Lab 5: Mixed-Signal Integration

A runnable mailbox experiment: separate clocks, analog readiness, coherent data, reset, and power-loss recovery.

What you will build and verify
  • Transfer one complete sample word between different clocks with a four-phase request/acknowledge protocol.
  • Block traffic until a defined analog-ready contract is valid, then release each reset on its local clock.
  • Observe how busy requests, stopped clocks, power loss, and restart affect delivery.
  • Use a self-checking testbench, recorded traces, and a deliberate negative control to distinguish evidence from assumptions.
Scope: this is a runnable digital integration experiment. It does not simulate analog metastability, converter settling, voltage collapse, physical isolation cells, or extracted timing. The payload is a 16-bit digital sample word supplied in the source clock domain. The power-good and ready inputs are already qualified logical signals from an assumed supervisor.

1. The interface problem

An analog block may take time to establish bias and reference levels, then produce a coded sample on its own clock. A controller may read that sample using another clock. A single-bit “ready” synchronizer does not automatically preserve the accompanying word, and a reset on only one endpoint can leave an old handshake state behind. These problems meet at the mixed-signal boundary.

This lab uses a one-entry mailbox. The producer offers a word with src_send; an offer is accepted only when src_ready is high at the source edge. The mailbox holds the accepted word while a request crosses to the receiver. The receiver captures it once and returns an acknowledgment. All four handshake phases must complete before another offer can be accepted. The receiver is assumed to consume every dst_valid pulse.

The architecture follows the stable-data handshake principles described in Cummings' CDC paper. Read lesson 39 first if synchronizer chains, multi-bit coherence, or recovery/removal are unfamiliar. Lesson 80 explains what must happen before a converter's digital word is meaningful.

2. State the analog contract before running

Signal or eventMeaning in this labWhat a physical implementation must add
analog_power_goodThe modeled analog supply contract is validReal thresholds, hysteresis, filtering, supply sequencing, and always-on circuitry
analog_readyBias/reference initialization has completed and samples may be acceptedA defined error band, settling/locking criterion, and behavior after disturbances
src_send && src_readyA complete source-domain word is accepted on this edgeSource setup/hold, voltage compatibility, and correct sample/valid alignment
dst_validThe receiver presents one captured word for this readout cycleA consumer that actually accepts it, or additional buffering/backpressure
Reset, power-good loss, or ready withdrawalBoth mailbox endpoints reset; outstanding delivery is canceledPhysical isolation, reset distribution, and an application recovery policy

The logical reset condition is por_n & analog_power_good & analog_ready. Each domain has a two-stage asynchronous-assert/synchronous-release chain. This compact expression models a contract; do not wire an unconditioned noisy comparator directly into a large reset tree merely because the simulation uses a Boolean AND. The reset architecture is discussed in the Cummings–Mills–Golson reset paper.

3. Run the supplied experiment

Install Python 3 and Icarus Verilog, with iverilog and vvp on PATH. The reference runs used Icarus 12.0. No PDK, network access, or SPICE tool is needed for the main lab. From the extracted learning directory:

cd labs/L05_mixed_signal_integration
python3 run.py

The runner compiles the three RTL modules and self-checking SystemVerilog testbench, then runs three clock/phase configurations. It returns an error if compilation fails, a test fails, a watchdog expires, or the expected result record is missing. Successful cases print:

PASS: all digital protocol assertions and directed tests passed

Use explicit paths when the tools are installed elsewhere, or set the IVERILOG and VVP environment variables:

python3 run.py --iverilog /path/to/iverilog --vvp /path/to/vvp
python3 run.py --case fast_source --waves

Fresh results go under run_results/; the delivered results/ directory preserves the recorded reference evidence. The optional --waves flag creates a VCD suitable for a waveform viewer. The CSV trace is readable without one. The README repeats the exact commands and tool requirements.

4. Follow the four phases

The source state machine has IDLE, WAIT_ACK_HIGH, and WAIT_ACK_LOW states. In IDLE it can latch a word and raise request. It then waits for synchronized acknowledgment, lowers request, and waits for acknowledgment to return low. Only then can another word be accepted. The destination captures only when synchronized request is high and its own acknowledgment is still low.

The data bus does not pass through sixteen independent synchronizers. Its coherence comes from being held stable while control traverses the handshake. The source must not overwrite that register while busy. A low request level must also reach the receiver between requests; otherwise a held request could be interpreted as one long transaction rather than two distinct words.

The two-stage control synchronizer and the receiving register are separate sequential steps. In the ideal event model, a request launched just before a readout edge is captured by stage one, reaches stage two on the following edge, and is acted upon by the receiver on another edge. That gives a nominal acceptance-to-capture interval between roughly two and three destination periods, depending on phase. It is not a bounded analog metastability resolution time.

For every completed run, accepted = delivered + aborted, with no outstanding word left. Busy offers are not accepted and do not appear in that accounting equation. Requests during reset/unready are also not accepted; the reset logic does not generate a busy-reject pulse for them. The source application must honor src_ready or retain and retry its own unaccepted offers.

Trace calculation: in the fast-source case, word 007F was accepted at 203.001 ns and delivered at 256.001 ns: 53.000 ns elapsed. The relevant readout edges were 212, 234, and 256 ns. Stage one, stage two, and the receiver account for those three edges. The 0.001 ns offset is the testbench's observation point after nonblocking assignments; it is not a modeled cell delay. 6. Inspect what the checker actually covers

ScenarioCheckFailure it can expose
Boot and power-good without analog-readyNo accepted word before qualificationPremature use of an unsettled analog interface
Normal transfers and rapid requestsOrdered expected-word queue; held-bus stability; accept/reject rulesOverwriting, corruption, duplication, or accepting while busy
Paused readout clockThe word remains outstanding and is delivered once after resumeAssuming a fixed number of wall-clock nanoseconds always completes a handshake
Power loss with readout stoppedBoth resets assert without readout edges; one pending word is canceledReset dependence on a stopped clock or stale delivery after restart
Analog-ready withdrawalCoordinated cancellation and fresh traffic after requalificationConflating power-good with valid samples
External resetClean restart; release aligned to each local clockAsynchronous release in this digital reset architecture

The checker observes accepted source words independently of the receiver and compares each delivered value against its queue. It rejects unsolicited outputs and old-epoch words. A watchdog catches loss of progress. These are directed tests with a stated coverage list, not an exhaustive proof of every reset ordering, clock waveform, input violation, or hardware failure mechanism.

7. Power loss creates a new communication epoch

The test pauses readout, accepts F001, and then removes power-good before delivery. The common asynchronous condition resets both endpoints even though readout has no edges. Restoring power-good alone does not release traffic: analog-ready must be re-established, and each reset chain releases on its own clock. A later BEEF word is delivered; F001 is not replayed.

The second deliberate cancellation withdraws analog-ready while power remains logically good. This models a lost bias/lock/settling contract. The test also performs a clean external reset after draining the channel. These cases share the same explicit rule: accepted-but-undelivered data is lost on cancellation. If loss is unacceptable, a higher-level design needs retention, a recoverable queue, or a retry protocol.

There is a further distinction: if the destination acted on a word just before failure but its acknowledgment never reached the source, the source alone may not know whether the action occurred. The testbench's global scoreboard can count it; real application logic needs transaction identifiers and recovery semantics for durable exactly-once actions. This mailbox makes no such guarantee.

8. Prove that a broken design is rejected

python3 run.py --case fast_source --negative-control

This command generates a temporary copy of the mailbox under run_results/ that overwrites the held word on every source edge. It leaves the supplied RTL unchanged. In the recorded run, the checker failed during rapid offers at 938.000 ns with mailbox changed while busy. The runner recognizes only that intended assertion failure as a successful negative-control demonstration.

A syntax error or arbitrary simulator crash is not accepted as proof that the data checker works. Read the log: it must fail for the expected reason. The recorded failing trace shows the distinction. This small experiment gives evidence that the test can detect the specific invariant the handshake relies on.

9. Take the design toward a physical ASIC

A two-stage synchronizer in RTL does not establish a SKY130 metastability MTBF. The cell choice, available resolution time, activity, voltage, temperature, placement, and characterization matter. Keep first-stage outputs out of functional fanout and preserve the interstage path. An ASYNC_REG attribute communicates intent; support and implementation behavior must be checked in the actual flow.

The held bus also needs a physical maximum-delay budget relative to the earliest allowed capture. In the nominal 22 ns readout scenario, the ideal control pipeline offers roughly 44–66 ns before capture, but routing, setup, clock uncertainty, and variation consume budget. Do not simply false-path the entire bus and assume it can take unlimited time. Derive a conservative bound from the actual protocol and report that the implementation meets it; inspect exception priority so a broad asynchronous clock-group declaration does not erase the intended check.

Reset assertion width, recovery/removal, distribution, and powered-off pin behavior also remain physical obligations. A Boolean ready flag must correspond to an analog condition with defined error and timing limits. The clock/power-state lesson separates clock stopping from real power removal, isolation, and retention. The lab's clock pause is not a characterization of an ICG cell.

10. Solved exercises and an optional synthesis bridge

Why not add two flip-flops to every bit of the data bus?

Independent bit synchronizers can capture different source instants and produce a word that never existed. The mailbox instead holds the entire word stable while synchronized control determines when to capture it. That protocol still requires the data to settle physically before the selected capture edge.

The consumer sometimes ignores dst_valid. Is the current mailbox sufficient?

No. The lab assumes an always-ready consumer. Add a holding output register with ready/valid flow control, or a FIFO, and define when acknowledgment means the word has been safely accepted. Do not acknowledge a transfer and then discard its only copy because the downstream consumer stalled.

Can a timeout clear only the source request and immediately accept another word?

Not safely without a designed cancellation protocol. The receiver may still be processing the old request or holding its acknowledgment. This lab cancels through a common reset of both protocol endpoints and starts a new epoch. Independent timeout recovery needs its own proof and tests.

The separate lesson 34 example maps a small enabled XOR into actual SKY130 cells and proves functional equivalence. It is not a synthesized or physically timed version of this mailbox. Run it offline with Yosys/ABC installed:

python3 synthesis_example/run_synthesis.py

It uses the bundled, checksum-verified reference Liberty and writes fresh outputs under run_results/synthesis/. The recorded result is two edfxtp_1 and two xor2_1 cells. The accompanying SDC is explicitly illustrative and was not executed as an STA run. Neither that small mapping nor this protocol simulation establishes silicon frequency, power, or reliability.

Key takeaways

  • A complete word, its validity, and its reset/power epoch belong to the same interface contract.
  • A held-data handshake solves coherence only when source stability and physical settling assumptions hold.
  • Busy rejection, clock pause, cancellation, and replay policy must be explicit.
  • Use observed logs and negative controls to understand what a test actually checked.
  • Digital protocol success complements analog and physical verification; it does not replace them.
