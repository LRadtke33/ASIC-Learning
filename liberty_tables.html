Reading Liberty Timing Tables

Every timing arc in a Liberty file is a grid of delay and output-slew values against input slew and load. This lesson reads one square, interpolates between squares, and passes one stage’s output slew to the next stage.

Where the numbers come from. The cell throughout is sky130_fd_sc_hd__inv_1 at the typical corner tt_025C_1v80: 25°C, 1.80 V. Time in the file is nanoseconds. Capacitance is picofarads.

What you will learn

  • Read one delay from a 7 × 7 table indexed by input slew and output load.
  • Interpolate between table points, and know when the timer must extrapolate.
  • Chain two stages by passing one cell’s output slew to the next cell’s input.

Where this fits · the flow map is lesson 8

In the flow
Inside every timing run, from step 3, synthesis to step 8, extraction and timing.
Tools
OpenSTA, built into OpenROAD, interpolates the tables. Commercial: PrimeTime, Tempus.
Why it matters
Knowing how a delay is looked up tells you when to trust it and when the timer is extrapolating.

Source scope. Exact inverter values and table axes below were rechecked against the archived SkyWater HD repository at revision ac7fb61f06e6. They are nominal library data, not a measured chip specification. Inverter data · units and templates.

1. A delay is one square in a table

cell_rise answers: the input is falling, so the output is rising. How long from the input's 50% point to the output's 50% point? The rows are the input slew. The columns are the load capacitance from lesson 21. Both axes are the seven points the library was simulated at.

This is the fastest input edge in the file, a 20–80 slew of 0.01 ns. Delay grows with the load, and the rise stays slower than the fall at every column.

The highlighted column, 9.52 fF, is the nearest simulated point to four inv_1 inputs (9.21 fF). At that load a fast input edge produces a rising output in 0.0728 ns and a falling output in 0.0455 ns. The output edge is not the same number: the rise transition stored beside this delay is 0.0877 ns, and the fall transition is 0.0477 ns. Lesson 25 uses that difference.

The table template is named del_1_7_7. Its axes are declared once for the whole library:

  • variable_1 : input_net_transition — the row. The seven values run from 0.01 ns to 1.5 ns. 1.5 ns is also max_transition on the input and default_max_transition for the library.
  • variable_2 : total_output_net_capacitance — the column. For inv_1 the last column equals max_capacitance, 0.181284 pF.

A real net almost never lands on a grid point. Four inputs are 0.009208 pF, which sits between 0.003565 pF and 0.009521 pF. Section 3 writes that straight line out: the rise delay is 0.071063 ns. The highlighted table cell, one column over, is 0.072847 ns. Quoting a number means saying which square, and whether the value was read from a square or from the line between two squares.

There are four tables on this arc, not one: cell_rise, cell_fall, rise_transition, fall_transition. Delay is when the 50% point arrives. Transition spans the edge from 20% to 80%. The transition becomes the next gate's input slew.

2. The lookup table is a 7 by 7 grid

The library header sets delay_model : table_lookup. That model is the non-linear delay model, usually called NLDM. A straight formula delay = D0 + D1 × slew + D2 × load is too stiff for a modern cell, so the file stores the SPICE result at a grid of slews and loads. The timer reads the grid. It does not rerun the transistors.

This inverter’s combinational arc has four timing tables. cell_rise and cell_fall are the delay of a rising and a falling output. rise_transition and fall_transition are the 20–80 output slews that go with those edges. The table is chosen by the output edge. This inverter is negative_unate, so a rising output comes from a falling input, and the row index for cell_rise is that falling input's slew.

Slew is in ns, load in pF, delay in ns. The last slew, 1.5 ns, is max_transition. The last load, 0.181284 pF, is max_capacitance on Y. A question past either end is outside the simulated grid. Tools still return a number there, by extending the edge of the table, and that extension is the less accurate read. Stay inside the squares that were simulated.

Both axes are geometric. Each slew is 2.30506 times the slew before it: 0.0230506 / 0.01 = 2.30506, and 1.5 / 0.01 = 150, whose sixth root is the same 2.30506. Each load is 2.67033 times the load before it: 0.00133517 / 0.0005 = 2.67034, and 0.181284 / 0.0005 = 362.568. Equal steps on a log axis are why the columns look bunched at the left of a linear plot and spread out at the right.

The header measures delay from 50% to 50% (input_threshold_pct_rise and output_threshold_pct_rise are both 50, and the same on the fall). Slew is 20% to 80% (slew_lower_threshold_pct_rise 20, slew_upper_threshold_pct_rise 80, both edges). slew_derate_from_library is 1.0, so the transition number in the table is already the slew the next lookup uses. Some other libraries measure a 10–90 edge and scale it. This file does not.

Delay does not grow with input slew in every column. On cell_fall, at the lightest load 0.0005 pF, the 0.650743 ns row is 0.0467306 ns and the 1.5 ns row is 0.0317479 ns. The slowest input edge is the smaller delay in that one column. Read the square. The trend in section 1 is the first row against load, where both edges do grow.

A very slow edge into a tiny load does get sharper. At input slew 1.5 ns and load 0.0005 pF, rise_transition is 0.152164 ns. At the highlighted load 0.00952062 pF and input slew 0.01 ns, rise_transition is 0.087680 ns, slower than the input. The cell restores the edge when the load is light and passes a slower edge on when the load is heavy. The next gate's row index is whichever of those the transition table returned.

3. Interpolation is the straight line between the nearest squares

Four inv_1 inputs are 4 × 0.002302 = 0.009208 pF. The input slew in this first example is exactly the first row, 0.01 ns, so only the load axis moves. 0.009208 sits between 0.00356533 pF and 0.00952062 pF.

The fraction of the way across that gap is

(0.009208 − 0.00356533) / (0.00952062 − 0.00356533) = 0.00564267 / 0.00595529 = 0.947505.

Rise delay, from the two cell_rise squares on that row:

0.0388749 + 0.947505 × (0.0728467 − 0.0388749) = 0.0388749 + 0.947505 × 0.0339718 = 0.071063 ns (71.06 ps).

Fall delay, from the two cell_fall squares on the same row (0.0252454 and 0.0454996):

0.0252454 + 0.947505 × (0.0454996 − 0.0252454) = 0.044436 ns (44.44 ps).

Those two results are the line drawn in figure 1. The table cell at 0.00952062 pF is 0.0728467 ns rise and 0.0454996 ns fall. The corner table in lesson 22, section 3 rounds this same 0.009208 pF line to 71 ps and 44 ps.

When the slew is off the grid as well, the read uses four squares. The worked point here is an input slew of 0.015 ns and a load of 0.006 pF. Both sit inside the shaded cell of the table above. This pair is a point chosen inside the grid so the arithmetic is visible. It is not a net that was extracted from a chip.

Load fraction, call it ty: (0.006 − 0.00356533) / (0.00952062 − 0.00356533) = 0.00243467 / 0.00595529 = 0.408825.

Slew fraction, call it tx: (0.015 − 0.01) / (0.0230506 − 0.01) = 0.005 / 0.0130506 = 0.383124.

First hold the slew at each neighboring row and walk the load fraction. At slew 0.01 ns: 0.0388749 + 0.408825 × (0.0728467 − 0.0388749) = 0.052763 ns. At slew 0.0230506 ns: 0.0439316 + 0.408825 × (0.078324 − 0.0439316) = 0.057992 ns.

Then walk the slew fraction between those two results: 0.052763 + 0.383124 × (0.057992 − 0.052763) = 0.054767 ns (54.77 ps). That is the dot in figure 2.

Walking slew first and load second lands on the same 0.054767 ns. Along the low load, 0.00356533 pF: 0.0388749 + 0.383124 × (0.0439316 − 0.0388749) = 0.040812 ns. Along the high load, 0.00952062 pF: 0.0728467 + 0.383124 × (0.078324 − 0.0728467) = 0.074945 ns. Then 0.040812 + 0.408825 × (0.074945 − 0.040812) = 0.054767 ns. The two orders are one bilinear read. Publishing either intermediate without the order is how the same point turns into two different stories.

The same fractions apply to cell_fall, rise_transition, and fall_transition. Each table has its own four numbers. One fraction does not transfer a rise delay into a fall delay.

One inv_1 input, 0.002302 pF at a 0.01 ns slew, falls between the 0.00133517 pF and 0.00356533 pF columns. Its fraction of the way across is (0.002302 − 0.00133517) / (0.00356533 − 0.00133517) = 0.433525, which gives a rise delay of 0.031344 ns and a fall delay of 0.020819 ns. Wire capacitance (lesson 21) is added to the pin capacitance before the lookup, because the column is one total capacitance. A resistive wire, whose delay grows along its length, needs the extracted net of lesson 28 instead.

4. The timer adds the delay and hands the slew to the next pin

For one arc the timer does four things.

  1. Pick the table from the output edge. A rising output uses cell_rise and rise_transition.
  2. Take the input slew from the previous arc's transition table. The library name for that axis is input_net_transition.
  3. Add the load: every receiver's pin capacitance, plus the wire capacitance on that net. The library name is total_output_net_capacitance.
  4. Interpolate. Add the delay to the arrival time at the 50% point. Store the transition result as the next pin's input slew.

Lesson 25 already walks two inv_1 cells on the exact 0.00952062 pF column, so only the slew axis is off a row. The first cell's rise_transition at input slew 0.01 ns is the table cell 0.0876798 ns. That number is the second cell's input slew. The second cell's output falls, so the delay comes from cell_fall. 0.0876798 ns sits between the rows 0.0531329 ns (fall delay 0.0615784 ns) and 0.122474 ns (fall delay 0.087258 ns).

(0.0876798 − 0.0531329) / (0.122474 − 0.0531329) = 0.0345469 / 0.0693411 = 0.498217.

0.0615784 + 0.498217 × (0.087258 − 0.0615784) = 0.074372 ns.

Lesson 25 rounds that read to 0.074 ns. The fastest-row fall at the same load is the table cell 0.0454996 ns. Using 0.01 ns as every stage's input slew makes the path look faster than the transition table says it is.

The arrival the timer stores is the time of the 50% point. Slew is carried beside it and is not added into the arrival. On a longer path the same pair of operations repeats: delay joins the arrival, transition becomes the next row index.

Constraint arcs use a different template. On dfxtp_1 the setup and hold tables are vio_3_3_1, indexed by the clock slew and the data slew, with no load column. The delay tables on Q are still the 7×7 del_1_7_7 grid. Clock-to-Q at the exact column 0.00900162 pF and clock slew 0.01 ns is the table cell 0.3279992 ns rising and 0.3040849 ns falling. Lesson 26 adds those to a path.

A second model, CCS, stores a current waveform instead of one delay and one slew. The numbers on this page are the table_lookup grids. The fast-corner name ff_n40C_1v95 is not one of the four plain tables in lesson 22, section 3.

Checkpoint: should 40 ps of slew be added to a 70 ps cell delay?

No. Add the 70 ps propagation delay to the arrival time. Pass the 40 ps transition to the next lookup, after accounting for interconnect. Slew describes the waveform width, not a second propagation delay.

Check your understanding — the load falls between two table columns. How does the timer get a delay?

It interpolates between the nearest characterized points in both slew and load. On the 0.01 ns slew row, four inv_1 inputs (0.009208 pF) interpolate to 0.071063 ns rise and 0.044436 ns fall. Outside the table it must extrapolate, which is less trustworthy.

Key takeaways

  • This inverter arc has four 7×7 timing tables: cell_rise, cell_fall, rise_transition, fall_transition. Rows are input slew. Columns are total output capacitance.
  • At the table cell 0.01 ns and 0.00952062 pF, inv_1 rises in 0.0728467 ns and falls in 0.0454996 ns.
  • Four inputs, 0.009208 pF, on that same slew row, interpolate to 0.071063 ns rise and 0.044436 ns fall. The worked off-grid point 0.015 ns and 0.006 pF interpolates to 0.054767 ns.
  • The timer adds the delay at the 50% point and uses the transition result as the next pin's input slew. On the 9.521 fF column that handoff is 0.0876798 ns in, then a fall of 0.074372 ns.
  • How a table like this is measured — a slew×load sweep, and a setup bisection — is lesson 24.
