Lesson 49 / 84 · Part VI, Physical cells and the floorplan

Endcaps

The last cell in a row was drawn to touch a neighbor. The end of the row has no neighbor. An endcap is the cell placed there so the rails and the well still finish.

Where the numbers come from. There is no cell named endcap in sky130_fd_sc_hd. The historical name is FP_ENDCAP_CELL in open_pdks/OpenLane; current LibreLane uses ENDCAP_CELL. Both examples select the same cell. [pinned flow configuration] The size and the devices are the decap_3 LEF and schematic spice.

What you will learn

  • Explain why a row cannot stop on a bare cell edge.
  • Identify decap_3 as the SKY130 HD endcap, and what the flow configuration says about it.
  • Terminate row fragments around macros, not only the outer edges of the core.

Why it matters
Rows must end in a way that satisfies the well and implant rules.

1. A row should not stop on a bare edge

Cells in a row are drawn to abut (lesson 13). The power rail, the well, and the implant of one cell are meant to land on the same shapes in the next cell. The last site of the row has nothing on its outer side. An endcap is a cell placed at that edge so those shapes still have a neighbor.

It is not a logic gate, and it is not the spacer that fills a hole in the middle of the row (lesson 47). The spacer continues a row that already has cells on both sides. The endcap is the cell that is allowed to be the last one.

2. In this library the endcap is decap_3

Searching this library for a cell named endcap does not find one. The historical OpenLane config sets

FP_ENDCAP_CELL sky130_fd_sc_hd__decap_3

decap_3 is class CORE, site unithd, SIZE 1.380 BY 2.720. Three sites. Same outline as inv_1. The schematic is two MOS capacitors, both the same widths on every decap in the family (lesson 52):

  • High-Vt PMOS, 0.87 µm wide, 0.59 µm long. Gate on VGND. Both channel ends on VPWR.
  • NMOS, 0.55 µm wide, 0.59 µm long. Gate on VPWR. Both channel ends on VGND.

Logic transistors in this library are 0.15 µm long. This channel is 0.59 µm. The cell is a capacitor between the rails, and it is also the cell the flow drops at the end of the row. It is one row tall on unithd, so it abuts the logic cell beside it.

The decap-insertion setting names a family, not the row-end master. In the current LibreLane example, DECAP_CELLS uses sky130_fd_sc_hd__decap*, while ENDCAP_CELL names one master. The endcap line is the one that names decap_3 exactly. Lesson 52 is the family. This page is only the row-end use.

Whether decap_3 has special boundary geometry — boundary poly, a drawn well edge, an implant that stops inside the cell — is a layout question answered by its GDS. The configuration, the LEF outline and the schematic establish which cell is used, its size and its two devices.

Three sites is 1.38 µm. A row whose width is an integer number of 0.46 µm sites can hold that cell on the end and still land on the grid. How many endcaps the placer actually drops, and whether both ends get one, is the placer's rule. The config names the cell.

3. The rail and the well do not start at the first logic cell

decap_3 at each end of the row is a full template: met1 rails, well, and the edge contract from lesson 17. The first logic cell then abuts another legal edge, on the left as well as on the right.

The rail the logic cell uses is the same stripe that runs through the endcap. Removing a required endcap changes the boundary conditions assumed by the flow. Whether a particular exposed edge is legal must be decided by the approved boundary cells and DRC rules; ordinary abutment by itself is not proof of a legal row termination. The row picture in section 1 is this stripe, seen from above.

4. Row fragments matter as much as the outside edge

A macro or placement blockage can split one row into several fragments. Each relevant boundary may need termination, including the new edges beside the macro. The endcap rule follows the remaining row geometry; it is not just “two cells per chip.” OpenROAD’s tap/endcap insertion handles row cutting and boundary placement.

EndcapLegal row boundary in a specified flowInterior tap coverage or enough local decoupling

FillerContinue the row template across a gapA legal exterior boundary in every library

Worked example: if a placement region contains 100 independent row fragments and this flow inserts one decap_3 at each end, the reservation is 100 × 2 × 3 = 600 sites. At 0.46 × 2.72 µm² per site, that is 750.72 µm². The count is assumed; it must be taken from the actual row-fragment geometry in a design.

Analog ↔ digital: a wide analog macro changes the nearby digital row boundaries. Its placement halo and well arrangement can affect endcaps, taps, routing access, and supply continuity together.

Check your understanding — May any same-size decap replace the endcap?

No. Matching the outline is necessary for placement, but the approved edge pattern, orientation, well/implant geometry, and flow/library rules also matter.

Check your understanding — a macro splits a row into two fragments. How many endcaps does that row need?

Four: one at each end of each fragment. The cells beside the macro have no neighbor either, so the fragment ends need terminating exactly like the outer edges of the core.

Key takeaways

  • An endcap is the cell at the outer edge of a row, so the rail and the well still have a neighbor.
  • This library has no cell named endcap. The LibreLane configuration uses decap_3.
  • decap_3 is 3 sites, 1.38 × 2.72 µm, class CORE.
  • Its devices are a 0.87 µm high-Vt PMOS and a 0.55 µm NMOS, both 0.59 µm long, wired as capacitors between the rails.
  • Boundary geometry inside decap_3 is a layout (GDS) question; the configuration, LEF and schematic establish the cell, its size and its devices.
  • The endcap continues the rail and gives the first logic cell a legal neighbor on its outer edge.
